# Codetrail 1.5.0

Codetrail now follows a whole team's repositories. Point it at a GitHub organization, an Azure DevOps project or a GitLab group, and one page shows what the team merged everywhere since you last looked, and why, with one estimate for catching up on all of them. Every earlier catch-up stays readable, by day from a calendar or over a range of dates, at no cost.

## Added

- **Teams from hosting services.** `codetrail team add`, `list`, `serve` and `remove` follow the repositories of a GitHub organization, an Azure DevOps project or a GitLab group, or a chosen set of them. Each repository gets its own guide. `codetrail team serve` shows every repository's "you're behind" signal and its guide under one sign-in, and the add-repositories screen picks the repositories from the page ([ADR 0020](https://github.com/mohamed-abdelsattar92/codetrail/blob/v1.5.0/docs/adr/0020-hosting-services-through-their-own-programs.md)).
- **Catching up across a team.** **Catch up** on the team page, or `codetrail team update <name>`, works in two steps:
  - First, for free: it re-reads the sources, clones new repositories and refreshes every repository's facts.
  - Then, once you agree: it shows one estimate, with a line and a checkbox per repository, capped at the team's budget (`[catch_up] max_budget_usd`).

  The team page then shows one card per repository with something new, busiest first: its digests' highlights marked documented or inferred, who merged, and **Mark read**. Above them, "Across the team" is an overview written in one call, which may only copy documented blocks from the digests.
- **Past catch-ups.** A page at `/team/catch-ups`, linked from the team page and its sidebar, reads any earlier catch-up again at no cost: its overview, each repository's digests, and what failed or was left out. Pick a day on a calendar of 53 weeks, or a range of dates; the dates stay in the page's address, so a week can be bookmarked (`[team] history_days`, `max_history_catch_ups`).
- **Highlights in digests.** Every digest carries up to three highlights, for every repository (`[team] highlights_per_digest`).
- **How-to guides for every feature**, one page each, with the steps, the commands, a screenshot at every step, the settings, the costs and troubleshooting ([docs/guides](https://github.com/mohamed-abdelsattar92/codetrail/blob/v1.5.0/docs/guides/README.md)). The teams guide covers following a team, catching up and going back to past catch-ups.

## Changed

- **The team pages look like the guides**, with the same header and sidebar, the theme switch and the language picker. A guide served by `codetrail team serve` links back to its team.
- **A guide with no pages yet says "No guide yet"** instead of "Up to date".
- **The "you're behind" signal counts from the commit the guide last covered**, so after `codetrail update --facts-only`, or a catch-up's free part, it still says how far behind the guide is ([ADR 0021](https://github.com/mohamed-abdelsattar92/codetrail/blob/v1.5.0/docs/adr/0021-count-behind-from-the-guide.md)).
- **The README and the getting-started guide install from PyPI**: `uv tool install codetrail-cli`.

## Fixed

- Stopping Claude Code or Codex closes their pipes at once, even while something they started outside their process group still holds them.
- The repository root's facts read "project · repository root" instead of `project:.`.
- The home card's "Started on" and the repository page's first commit show the same date.
- On an Arabic page, the documented and inferred labels are in Arabic too.
- Layout fixes: the phone menu, tall dialogs, diagrams, long diffs and fact ids, and the update and catch-up panels.

## Security

- **Codetrail never holds a hosting token.** It reads GitHub, Azure DevOps and GitLab through your own `gh`, `az` or `glab`, read only, and clones with your own git sign-in.
- **Budgets can't be passed.** Each paid call reserves its largest possible cost before it starts, so no call starts past an update's or a team's budget. A call that fails, or is stopped, after the provider counted it still counts.
- **More of what a repository holds is scanned for secrets:**
  - compressed files and PDFs;
  - every file gitleaks' defaults skip;
  - texts that start like a binary file, such as commit messages, page titles, guided paths and digest titles.
- **Codetrail's folders and files are private to you** (0700 and 0600), git's mirror included.
- **Text a repository plants can do less.** Links on the page open only `http`, `https` or relative addresses. A crafted `.codetrailignore` can't hang an update. A planted bare repository can't run a command through a provider's `git status`. Everything a prompt carries from the repository is fenced as data.
- **Providers run with less.** Claude Code calls deny every MCP tool and turn off auto memory and claude.ai connectors. Codex runs with web search off and isn't used for grading or the team overview.
- **The agent guardrails are tighter.** The git hooks refuse to run when a check could be skipped. Agents' searches that would reach an env or key file are refused. Claude Code asks before an agent edits a guardrail.
- **Dependencies with known vulnerabilities are updated**: certifi, opentelemetry-api and, in the commit-message tooling, fast-uri.

## Install or upgrade

If you installed Codetrail from PyPI:

```bash
uv tool upgrade codetrail-cli
```

Otherwise, install this release:

```bash
uv tool install --reinstall codetrail-cli==1.5.0
```

```bash
codetrail --version
```

If you installed 1.4.0 or earlier, run `uv tool uninstall codetrail` once first, since both tools put a `codetrail` command on your `PATH`.

Your targets, guides and settings carry over unchanged, and Codetrail upgrades its own databases the first time it opens them. Some things are stricter now:
- An update whose budget is smaller than a single call's cap refuses before calling anything; raise the budget, or lower the cap, in your settings.
- A `.codetrailignore` over the new size and line limits fails the refresh with the reason.
- Following a team needs the service's own program installed and signed in: `gh`, `az` or `glab`.

The full list is in the [changelog](https://github.com/mohamed-abdelsattar92/codetrail/blob/v1.5.0/CHANGELOG.md).
