# Codetrail 1.4.0

Codetrail is now your repository's tutor for you and your coding agent. Each update also writes what Codetrail understands about the repository in a form made for agents, so Claude Code or Codex starts a task from a map of the repository and the brief for the area it's changing, instead of rediscovering the code each session. Diagrams on the page are drawn with D2 and laid out by ELK.

## Added

- **Context for coding agents.** Each update writes two things to Codetrail's data folder, never to the repository:
  - **a map of the repository:** its parts and how they connect, its decisions, recent changes and the guide's pages, built from the facts Codetrail extracted, so it costs nothing;
  - **a brief per area and concept page:** its key files, its conventions and the reasons for them, each reason still marked documented (quoted and checked) or inferred.

  The briefs come from the call that already writes each page, so each estimate grows only a little. A brief whose code changed since it was written says it may be stale.
- **`codetrail mcp <target>`**, a read-only tool server that Claude Code and Codex start themselves. It offers four tools:
  - `codetrail_map` before a task;
  - `codetrail_brief` before changing an area;
  - `codetrail_page` for a whole guide page;
  - `codetrail_changes` for what changed since a commit or a date.

  Nothing an agent asks for costs a call.
- **`codetrail agents <target>`** prints the two commands that connect Claude Code and Codex, and you run them yourself. The getting-started guide has a new section, "Use Codetrail with your coding agents".

## Changed

- **The README** presents Codetrail as your repository's tutor, for you and your coding agent: what each of you gets, a section on the context for coding agents with excerpts of a real map and brief, and the agent's path in the "How it works" diagram.
- **Every diagram is drawn with D2 and laid out by ELK.** This covers the system diagram, and the imports, dependencies and resources diagrams on area pages, guide pages and answers. Lines are right-angled and evenly spaced, so busy diagrams stay readable, and each kind of part keeps its own shape. The first diagram on a page takes about a second and a half to appear while the browser prepares D2. The README's diagrams are drawn with D2 too.

## Security

- **The tool server only reads.**
  - It speaks over standard input and output, with no network port.
  - It reads only Codetrail's export: no file of your repository, no git, no assistant.
  - It checks every argument, and it never holds the update's lock.
- **The tool server can't run code planted in a repository.** The printed command runs Python with `-I`, so code in the folder an agent works in never runs.
- **Each tool says which repository it covers**, and tells agents in any other repository not to call it.
- **The page's Content-Security-Policy no longer allows inline styles**, which only Mermaid needed. D2's layout evaluates JavaScript, so it runs in a worker with its own policy that can load nothing but its own files and can't reach the page. Its drawing is shown as an image, which can't run script or follow links.

## Install or upgrade

```bash
uv tool install --reinstall git+https://github.com/mohamed-abdelsattar92/codetrail@v1.4.0
```

```bash
codetrail --version
```

Your targets, guides and settings carry over unchanged. Pages written before 1.4.0 have no brief yet: until an update rewrites or revises them, Codetrail derives one from the page. To connect your agents, run `codetrail update <target>` (or `codetrail agents <target>` to build the context from what you already have), then the two commands it prints. The full list is in the [changelog](https://github.com/mohamed-abdelsattar92/codetrail/blob/v1.4.0/CHANGELOG.md).
