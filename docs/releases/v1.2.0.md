# Codetrail 1.2.0

Two new pages show what your repository is and how well it explains itself, drawn as charts you can explore, and the sidebar gets out of the way when you want the whole width. None of it calls your assistant: everything here is read from the code, its history and the guide, for free.

## Added

- **The Documentation page** (in the sidebar, or **G** then **O**) shows how well the repository explains itself: how much of the guide's rationale is documented and from where (ADRs, documents, code comments, commits), which commits explain why, which ADRs need attention, and which dependencies, projects and resources no document mentions. An overview shows each number with its bar and its trend across updates; each section opens to a chart and the items behind it, the one most in need first, and the long lists filter by kind. `codetrail metrics <target>` prints the same numbers.
- **The Repository page** (in the sidebar, or **G** then **T**) shows what the repository is, as charts you can explore: a timeline of commits by day, week or month that you can range over and pan, with the releases from its tags and the dependencies that arrived and left; a calendar of the last year, day by day; a heat map of where change happens by guide area, folder or file, beside how much of each area's rationale is documented; and its lines of code by language with the share in tests, commit types and sizes, quiet code, and facts by kind. Every number is in a table under its chart, and no author is read or shown. `codetrail stats <target>` prints the summary.
- **A sidebar that gets out of the way.** Hide it with the button at the start of the header, or **\\**, and the page takes the whole width; rest the pointer on the window's edge to peek at it. Its sections fold, and the pages you pin sit as tiles at its top, kept by Codetrail so they follow you to any browser. The page now sits in a card inside a tinted frame.
- Home cards for both pages, in English and Arabic like the rest of the interface.

## Changed

- **Codetrail's mirror keeps the tags that point into your branch**, for the releases on the Repository page. Tags elsewhere, and their commits, still never come in.

## Fixed

- **The first update of a new target, started from the page**, no longer fails now and then with "table … already exists", or leaves the database locked, when the page reads the database while the update creates it.

## Security

- **A revision read from Codetrail's data folder can no longer be taken by git as an option**, and a `source.json` whose commit isn't a full commit name is refused, with a message to run the update again.

## Install or upgrade

```bash
uv tool install --reinstall git+https://github.com/mohamed-abdelsattar92/codetrail@v1.2.0
```

```bash
codetrail --version
```

Your targets, guides and settings carry over. Each target's database gains a table for the metrics' trends the first time Codetrail opens it, so the trends start with your next update; the next update also fetches your branch's tags for the releases. The full list is in the [changelog](https://github.com/mohamed-abdelsattar92/codetrail/blob/v1.2.0/CHANGELOG.md).
