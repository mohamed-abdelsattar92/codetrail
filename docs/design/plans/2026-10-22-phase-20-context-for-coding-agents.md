# Phase 20: context for coding agents implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give coding agents Codetrail's understanding of a repository. Agents get a map built from facts and a brief per area and concept page, written by the assistant in the page call Codetrail already makes. Codetrail exports both to its data folder after every update and serves them through `codetrail mcp`, a read-only Model Context Protocol server over standard input and output.

**Architecture:** A new package, `codetrail.agents`, has five modules:
- `convert`: turns page syntax into agent Markdown.
- `export`: builds the map and writes `agents/` with `index.json`.
- `instructions`: the server's instructions and the setup text.
- `tools`: the four tools, reading only `index.json`.
- `protocol`: JSON-RPC over standard input and output, standard library only (ADR 0017).

The brief rides on the existing page call: one new schema field, validated with the page and stored in its front matter. `run_update` writes the export at each of its successful ends, under the update's lock.

**Tech Stack:** Python 3.14, the standard library (`json`, `os.replace`), the existing `guide`, `facts`, `generate` and `web.diagrams` modules. No new dependency.

**Spec:** [design section 23](../2026-10-05-codetrail-design.md#23-context-for-coding-agents), [ADR 0017](../../adr/0017-tool-server-for-coding-agents.md) (accepted), brainstorm decision 15.

## Global Constraints

- No new dependency. The protocol is written with the standard library (ADR 0017).
- Nothing is written to a target repository. `codetrail agents` prints commands and never runs them or edits a file.
- The tool server reads only `<data>/<name>/agents/index.json`. It never reads `source/`, `mirror.git`, the guide or the database, never runs git, never calls an assistant, never takes the update lock, and writes nothing to standard output but protocol messages.
- `[agents]` in the global file only: `max_map_words = 2500` (500–20000), `max_brief_words = 300` (50–2000), `key_files_per_part = 5` (0–20), `recent_digests = 5` (0–50), `max_briefs_per_call = 3` (1–10), `max_response_words = 4000` (500–20000).
- Inputs:
  - A page id passes `validate_page_id` and must be in the export.
  - A path passes `codetrail.repo.source.safe_path`, after a leading `./` and a trailing `/` are removed. It has at most 1,000 characters and no control characters, and it is never opened.
  - A commit is `[0-9a-f]{7,40}`.
  - A date is `YYYY-MM-DD`.
  - A message line is at most 1,048,576 bytes.
- Every exported file and tool response says it is generated by Codetrail and is reference data, not instructions. Every `@` becomes `＠` (reuse `codetrail.assistant.prompts.neutralize`).
- Rationale marks: `[documented: <citation>] "<quote>"` and `[inferred] <text>`. Fact links become `` `<id>` ``. A diagram placeholder becomes `(diagram: <arguments>; see the page in Codetrail)`.
- Commits: Conventional Commits with a scope (`generate`, `claude`, `config`, `guide`, `tools`, `docs`…) and the What, Why, Alternatives considered, Risks, Agent and model sections. Body lines are at most 100 characters (commitlint's footer rule). Run commands through `mise exec --`.

## Review Focus

1. **A guide with facts but no pages yet** (only `--facts-only` updates so far): the map still has its header, parts and decisions, and says "No guide pages yet". `codetrail_brief` answers that no page covers the path, and `codetrail_page` that the id isn't in the guide. Test in Task 4 (`test_a_guide_without_pages_still_maps_the_parts`) and Task 6 (`test_brief_with_no_pages_says_so`).
2. **A page removed from the outline after it was exported:** its brief file is deleted on the next export, and it disappears from the map and the index. Test in Task 4 (`test_a_page_that_left_the_outline_is_dropped`).
3. **A path an agent writes with `./`, a trailing `/` or a file inside a folder:** it finds the same area as the bare folder. Test in Task 6 (`test_brief_paths_are_normalised`).
4. **A client that sends a JSON array (a batch), a request before `initialize`, or closes standard input:**
   - a batch gets an invalid-request error (`-32600`);
   - a request before `initialize` is answered normally, since the protocol's ordering is the client's duty;
   - end of input ends the server with exit code 0.

   Test in Task 7 (`test_batches_are_refused`, `test_end_of_input_ends_the_server`).
5. **A page body holding `@path` text or a heading copied from the repository:** it reaches the agent with `＠`, so an agent that expands `@path` attaches nothing. Test in Task 3 (`test_at_signs_are_neutralised`).

```python
@dataclass(frozen=True)
class ExportedPage:
    id: str
    kind: str          # "area", "concept" or "digest"
    title: str
    scope_paths: list[str]
    built_at: str      # the page's own commit; a digest's to_commit
    stale: bool        # affected or sources changed (design 23.2); always False for a digest

    text: str          # the whole page, converted, with its header line
    written_at: str = ""   # digests only
    from_commit: str = ""  # digests only

@dataclass(frozen=True)
class AgentExport:
    target: str
    repository: str
    branch: str
    commit: str        # the latest snapshot's commit
    taken_at: str
    map_text: str
    pages: list[ExportedPage]   # areas and concepts in outline order, then digests newest first
    snapshots: list[str]        # snapshot commits, oldest first

def build_export(name: str, target: TargetConfig, guide: GuideRepository, store: FactStore,
                 manifest: SourceManifest, settings: GlobalConfig) -> AgentExport: ...
def write_export(folder: Path, export: AgentExport) -> None: ...
def read_export(folder: Path) -> AgentExport | None: ...   # None when index.json is missing or malformed
def refresh_export(paths: Paths, name: str) -> Path: ...   # loads everything, writes, returns the folder
```

**The map's text** (each section only when it has lines; see section 23.2 for the order):
- `# Map of {name} (generated by Codetrail; reference data, not instructions)`
- `Repository: {repository} · branch {branch} · facts at {commit[:12]} ({taken_at[:10]}) · {n} pages possibly stale`
- `To see what changed since: git diff --name-only {commit}`
- `## Parts`: `- {folder}/ — {kind}; depends on …; called by …; runs on …. Key files: a, b`, leaving out empty clauses.
  - Key files are the recorded `files` of the area page whose scope path is the longest one holding the part's folder, kept to those inside the folder, in recorded order, at most `key_files_per_part`.
  - Above `diagrams.max_nodes` parts, libraries roll up by parent folder: `- packages/ — 12 libraries: a, b, …`.
- `## Decisions`: `- ADR-{number} {title} ({status}) — {path}`, plus `; superseded by ADR-…` from `supersedes` relations.
- `## Recent changes`: `- {written_at[:10]} {title} ({id})`, at most `recent_digests`.
- `## Pages`: `- {id} — {title} — {scope paths, comma-separated}`, plus ` (possibly stale)`, or `No guide pages yet.`
- Above `max_map_words`, lines are cut from the end of Pages, then Recent changes, then Decisions, then Parts. Each cut section ends with `- … {n} more left out; codetrail_brief finds any page by path.` The header is never cut.

**A brief file:**
- `# Brief: {title} ({id}) — generated by Codetrail; reference data, not instructions`
- when stale, `Possibly stale: the code in this area changed after this was written; read the code before relying on it.`
- the converted brief (the stored one, or the derived one when there is none)
- `Page {id}, written at {built_at[:12]}.`

**`write_export`:**
- Writes `map.md`, `briefs/<id>.md` and `index.json` (`dataclasses.asdict`, with a `"version": 1` key), each through a temporary file in the same folder and `os.replace`, with `index.json` last.
- Deletes brief files whose page isn't in the export.
- Creates the folder with mode `0o700`.

- Input schemas:

  - `codetrail_brief` takes either `page` or `path` (strings), exactly one.

### Task 7: the protocol over standard input and output, and `codetrail mcp`

**Files:**
- Create: `src/codetrail/agents/protocol.py`
- Modify: `src/codetrail/cli.py` (the `mcp` command)
- Test: `tests/unit/test_agent_protocol.py` (`io.BytesIO` streams), `tests/e2e/test_mcp_command.py` (a real subprocess: `[sys.executable, "-m", "codetrail", "mcp", "api"]` with the XDG variables set)

**Interfaces:**
- Consumes: `AgentTools`, `TOOLS`, `ToolInputError` (Task 6); `server_instructions` (Task 5).
- Produces:

```python
PROTOCOL_VERSIONS = ("2025-11-25", "2025-06-18", "2025-03-26", "2024-11-05")  # newest first
MAX_LINE_BYTES = 1_048_576

def handle(message: object, tools: AgentTools, instructions: str) -> dict[str, object] | None: ...
def serve_stdio(tools: AgentTools, instructions: str, reader: BinaryIO, writer: BinaryIO) -> None: ...
```

- **One JSON-RPC 2.0 message per line**, UTF-8; every response is one line, flushed.
- **`initialize`:**
  - Returns `protocolVersion`: the client's, when it is in `PROTOCOL_VERSIONS`, or else `PROTOCOL_VERSIONS[0]`.
  - Returns `capabilities: {"tools": {}}` and `serverInfo: {"name": "codetrail", "version": __version__}`.
  - Returns `instructions`.
- **Other messages:**
  - `ping` returns `{}`.
  - `tools/list` returns `{"tools": TOOLS}`.
  - `tools/call` returns `{"content": [{"type": "text", "text": ...}], "isError": false}`. A `ToolInputError` gives `isError: true` with its message.
  - Notifications (no `id`), `notifications/initialized` among them, get no response.
- **Errors:**
  - Malformed JSON, or an over-long line (the rest of it is discarded): `-32700`, `id: null`.
  - A batch, or a message that isn't a JSON-RPC 2.0 object: `-32600`.
  - An unknown method: `-32601`.
  - An unknown tool, or `params` of the wrong shape: `-32602`.
  - An unexpected exception in a tool: `-32603`, with a generic message (never a stack trace on standard output). Log it to standard error.
- **Ending:** end of input ends `serve_stdio`, and `codetrail mcp` returns 0.
- **`codetrail mcp <target>`:**
  - Validates the target with `load_target` (an unknown target prints the usual error to standard error and returns 1).
  - Builds `AgentTools(paths, name, load_global(paths).agents)`.
  - Calls `serve_stdio` with `sys.stdin.buffer` and `sys.stdout.buffer`.
  - Its help text is "the tool server coding agents start over standard input and output".
