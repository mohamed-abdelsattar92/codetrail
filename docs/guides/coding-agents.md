# Use Codetrail with your coding agent

Codetrail gives Claude Code, Codex or another coding agent the same understanding of a repository that you read in the guide. The agent reads a short map and a brief for the area it is about to change, instead of rediscovering the repository in every session. Use this when you ask an agent to change code in a repository that has a Codetrail guide.

**Before you start:** [write the repository's guide](first-guide.md). The map and the briefs come from it. The examples use a repository added as `shop`; use your own target's name.

## What the agent gets

Every update writes this to `~/.local/share/codetrail/shop/agents/`:

- **A map**, `map.md`. It names the repository's parts and how they connect, its decisions (ADRs), the latest digests and the guide's pages. It stays within `[agents] max_map_words`.
- **A brief for each area and concept page.** It lists the page's key files, its conventions and the reasons for them. Each reason is marked `[documented: <path>#L<start>-L<end>]` with its verified quote, or `[inferred]` for the assistant's own reading of the code.

Every file says it is generated by Codetrail, names the commit it describes and says it is reference data, not instructions. A brief whose page is out of date says it is possibly stale at the top.

## Connect your agent

1. Run:
   ```bash
   codetrail agents shop
   ```
   This rebuilds the export from the current guide and facts, then prints the commands to connect an agent. It runs none of them and changes none of your files. This is the output (the paths on your machine differ):
   ```
   Codetrail's context for coding agents is in ~/.local/share/codetrail/shop/agents.

   Connect Claude Code (registered for your user, so it works in every worktree of the repository):

       claude mcp add --scope user codetrail-shop -- ~/.local/share/uv/tools/codetrail/bin/python -I -m codetrail mcp shop

   Connect Codex:

       codex mcp add codetrail-shop -- ~/.local/share/uv/tools/codetrail/bin/python -I -m codetrail mcp shop

   Without the tool server, an agent can read the map at the start of every task: add this line to an instruction file
   that isn't committed and applies only to this repository. Never put it in a committed CLAUDE.md or AGENTS.md, where
   a path in your home folder would reach everyone's history:

       @~/.local/share/codetrail/shop/agents/map.md
   ```
2. Copy the command for your agent and run it yourself, in your own terminal. For Claude Code:
   ```bash
   claude mcp add --scope user codetrail-shop -- <python> -I -m codetrail mcp shop
   ```
   For Codex:
   ```bash
   codex mcp add codetrail-shop -- <python> -I -m codetrail mcp shop
   ```
   Copy the whole line from your own `codetrail agents` output. It holds the full path of the Python that runs Codetrail on your machine, in place of `<python>`.

Claude Code's command registers the server for your user, so it also works in the repository's worktrees, whose folders differ from the checkout's. The registration lives in your own agent settings. Nothing is written into the repository.

With several repositories, run `codetrail agents <name>` for each one. Each becomes its own server, `codetrail-<name>`.

## What the agent does with it

When the agent starts, the server tells it which repository it covers and how to use it: call `codetrail_map` before a task and `codetrail_brief` before changing an area. In any other repository the agent ignores the server.

The server offers four tools:

| Tool | Takes | Returns |
|---|---|---|
| `codetrail_map` | Nothing. | The map. |
| `codetrail_brief` | A page id, or a path in the repository. | The brief of that page, or of the area and concept pages that cover the path. Each says if it is possibly stale. |
| `codetrail_page` | A page id, such as `areas/api` or `concepts/contract-first`. | The whole guide page, for the full explanation behind a brief. |
| `codetrail_changes` | A commit (7 to 40 lower-case hexadecimal characters) or a date (`YYYY-MM-DD`). | The digests since then, newest first. |

Every answer ends with the commit it describes. To see what changed since then, the agent runs `git diff --name-only <commit>` in its own checkout; the map gives the command.

## Use the map without the tool server

If you don't want the tool server, an agent can still read the map at the start of every task.

1. Copy the `@` line that `codetrail agents shop` printed.
2. Add it to an instruction file that is not committed and applies only to this repository.
3. Never put the line in a committed `CLAUDE.md` or `AGENTS.md`. The path holds your home folder, which would reach everyone's history.

## What the agent can read

The tool server reads only Codetrail's own export, one file, `index.json`. That holds the map, the briefs, the guide's pages and the digests. They were built from the files Codetrail allows itself to read, scanned for secrets and checked. So the export adds no new way for a secret to leak.

The server does not read the repository, the mirror or the guide's files. It writes nothing, runs no git, listens on no port and calls no assistant. Only a program you run, such as your agent, can start it.

Text in the export came from an assistant reading the repository. Every response says it is reference data, not instructions, and tells the agent to read the code before relying on it. Treat an `[inferred]` line or a possibly stale brief as a hint, not a rule.

## Costs

Nothing an agent asks for costs a call to an assistant. The tool server calls no assistant. The briefs are written in the same call that already writes each page, so their small extra cost is part of the update's estimate, which you approve before it runs. See [Keeping the guide up to date](updating.md).

## Settings

In `~/.config/codetrail/config.toml`:

| Setting | Default | What it does |
|---|---|---|
| `[agents] max_map_words` | 2500 | Longest the map may be (500 to 20,000). Parts of it are shortened from the end when it would be longer, and the map says how many were left out. |
| `[agents] max_brief_words` | 300 | Longest one brief may be (50 to 2,000). |
| `[agents] key_files_per_part` | 5 | Key files listed for each part in the map (0 to 20). |
| `[agents] recent_digests` | 5 | Latest digests listed in the map (0 to 50). |
| `[agents] max_briefs_per_call` | 3 | Briefs `codetrail_brief` returns for one path (1 to 10). |
| `[agents] max_response_words` | 4000 | Longest answer of any tool (500 to 20,000). |

## Troubleshooting

| Message | Meaning and fix |
|---|---|
| `Codetrail has no context for shop yet: run codetrail update shop or codetrail agents shop.` | The target has no export yet. Run either command. |
| `Codetrail no longer has the target 'shop'.` | The target was removed after the agent connected. Remove the server from your agent, or add the target again. |
| `No page covers <path>; the map's Pages list what the guide covers.` | No area page covers that path. Ask for a page from the map's list. |
| `A page id looks like areas/<name> or concepts/<name>.` | The page id has the wrong shape. Copy an id from the map. |
| `Give a commit (7 to 40 lower-case hexadecimal characters) or a date (YYYY-MM-DD).` | `codetrail_changes` got something else. |
| `(cut at 4000 words; ask for one page with codetrail_page or codetrail_brief.)` | An answer passed `max_response_words`. Ask for a smaller piece, or raise the setting. |
| `No target named 'shop'. Add it with: codetrail target add shop <path>` | The name doesn't match a target. Check the spelling. |

If the agent can't start the server, run the same command from your own terminal. `codetrail mcp shop` waits for input from the agent and prints nothing else, so stop it with Ctrl-C.
